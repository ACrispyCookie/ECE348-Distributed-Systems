--==== SERVER ====--
Μεταγλώττιση:
Το πρόγραμμα μπορεί να μεταγλώττιστει με την χρήση του Makefile.
Παρέχεται η επίλογη παραγωγής τελικού εκτελέσιμου με εκτύπωση παραπάνω μηνυμάτων για απασφαλμάτωση,
με την εντολή make DEBUG=1 και επιπλέον επιλογές για Virtual Packet Loss:
π.χ. make REQUEST_LOSS=10
π.χ. make REPLY_LOSS=50

Υλοποίηση:
Χωρίζεται σε 4 διαφορετικά αρχεία:
  1. server_app.(h|c) - Εφαρμογή που χρησιμοποιεί το API και διαθέτει workers για primality testing
  2. server_api.(h|c) - Ορίζει τις βασικές λειτουργίες του API που είναι διαθέσιμες στην εφαρμογή
  3. internal_server.(h|c) - Ορίζει τις ρουτίνες των διαφορετικών νημάτων που τρέχουν
  4. utilities.(h|c) - Περιέχει διάφορες βοηθητικές συναρτήσεις κυρίως για την διευκόλυνση προσπέλασης των δομών δεδομένων (thread-safe)

--==== CLIENT ====--
Μεταγλώττιση:
Καθώς το πρόγραμμα είναι γραμμένο σε Python είναι απευθείας εκτελέσιμο μέσω
του interpreter της Python π.χ. python3 client_app.py

Υλοποίηση:
Χωρίζεται σε 2 διαφορετικά αρχεία:
  1. clinet_app.py - Εφαρμογή του αντίστοιχου client για την εφαρμογή primality
  2. clinet_api.py - Υλοποίηση του πρωτοκόλλου από την μεριά του client

--==== TESTING ====--
Για την δοκιμή χρησιμοποιήθηκαν τα εξής test:
  Βασικά tests:
    1. Κανονικό flow: HANDSHAKE -> REQUEST -> REPLY -> ACK και πάλι από την αρχή
    2. Retransmission μετά από κάποιο χρονικό διάστημα
    3. Retransmission μετά από το αντίστοιχο ACK για να δούμε την απόρριψη
    4. Duplicate που καθυστέρησε να φτάσει
    5. Request σε service που δεν εξυπήρετείται
    6. Έλεγχος cancel request μετά από restart και συνέχεια κανονικής ροης
    7. Παρατήρηση αλλαγών στους buffers ανάλογα με το πρωτόκολλο
  Extensive (black-box) tests:
    1. Χρήση του stress_test.py για διάφορες δοκιμές σε μεγάλη διάρκεια χρόνου
    2. Χρήση του rapid_fire.py για δοκιμασία του thread-safe αλλά και μέτρηση απόδοση (throughput)
  Packet loss:
    1. Εφαρμογή Virtual Packet Loss 5% και παρατήρηση της επίπτοσης στην απόδοση
    2. Εφαρμογή Virtual Packet Loss 15% και παρατήρηση της επίπτοσης στην απόδοση
    3. Εφαρμογή Virtual Packet Loss 50% και παρατήρηση της αυξημένης αποτυχίας στα αιτήματα
  Multiple clients:
    1. Δοκιμή πολλαπλών clients σε επικοινωνία με έναν server
    2. Δοκιμή πολλαπλών clients με round-robin load balancing σε πολλούς servers
  Discovery:
    1. Δοκιμή με πολλαπλούς ανοιχτούς servers για να παρατηρήσουμε οτι το discovery τους βρίσκει όλους
